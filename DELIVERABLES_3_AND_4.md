### Deliverable 3: Added Functionality Explanation & Justification

To surpass the static reference website, this solution introduces an **Interactive Multi-Stage Practice Studio** featuring a live, browser-native **WASM SQLite Query Engine**, an **Excel Formula Evaluator**, and a **Socratic 3-Tier Progressive Hint System**. Rather than providing static text or prone-to-hallucination conversational AI chatbots (which often "dump" answers directly to students), this feature creates an active learning sandbox. Students can write real SQL queries (`SELECT`, `GROUP BY`, `HAVING`, `JOIN`) directly against pre-loaded audit schemas (such as NYC Film Permits and General Ledgers) and execute them in real-time, receiving instant column and row-count schema diffs against expected accounting results. Furthermore, the 3-tier progressive hint system forces structured problem-solving by revealing conceptual guidance before syntactical skeletons, directly solving the problem of answer leakage while fostering genuine technical fluency required in accounting analytics.

### Deliverable 4: Starting Material Difficulty Analysis

The starting materials for this case make it significantly more challenging than previous course assignments due to the shift from guided, single-dataset exercises to an unguided, multi-domain software engineering and pedagogical task. In prior cases, students were provided structured Excel files or isolated SQL prompts with explicit step-by-step instructions. In contrast, this assignment requires students to synthesize diverse accounting sub-disciplines—such as internal control auditing, general ledger reconciliation, M&A cash flow discounting (NPV), and managerial cost allocation—into a unified, fully interactive web application. Additionally, curating clean, realistic financial datasets that compile cleanly within a client-side WebAssembly SQLite environment requires rigorous domain knowledge of both data pipeline engineering and standard financial accounting principles.
